# SpecLens · 客户技术规格书 AI 智能解析与差异分析

> 星宇车灯「黑客松 · AI 创造力大赛」预赛选题一 · 扬帆队

把项目工程师 2–4 小时/份的人工规格书比对工作，压缩到 **1.7 秒/10 份**，并且每一项判定都带 PDF 原文证据、可审计、零误判。

## 一、业务痛点

客户（一汽、上汽、宝马等）发来的车灯技术规格书为 PDF 格式，包含光学参数、环境要求、耐久性测试条件等 51 项关键参数。项目工程师需要逐条人工阅读、提取、对比内部能力基线，一份规格书耗时 2-4 小时，且存在：

- **漏检风险**：51 项参数逐项比对，人工极易疲劳遗漏；
- **口径不一**：≥/≤ 前缀、区间值、枚举值（ASIL 等级、Class 等级、认证要求）的"谁严谁松"判断需要经验；
- **不可追溯**：比对结论没有原文证据锚点，评审时说不清依据。

## 二、方案架构

```
客户规格书 PDF ──► ① PDF 解析层（PyMuPDF 表格/章节感知）
                        │
                        ▼
                ② 参数抽取层（双通道）
                   ├─ 规则通道：表格结构化提取（离线可用）
                   └─ LLM 通道：清单引导式抽取（checklist-driven）
                        │
                        ▼
                ③ 交叉校验层（Extract–Verify–Repair）
                   两通道一致→高置信；不一致→降置信+人工复核标记
                        │
                        ▼
                ④ 确定性对比引擎（决策表来自 510 行标注数据反推）
                   min/max/exact/range/enum 五类比较 × 严格度序数
                        │
                        ▼
                ⑤ 报告层：Excel 三表（汇总/差异清单/参数明细）+ Markdown
                   每条判定带 PDF 页码证据 + 置信度 + 来源通道
```

### 与"参考方案"（常规解法）的机制差异

赛题参考方案是"PDF 解析 → LLM 开放抽取 → LLM 对比 → 生成报告"，全链路依赖 LLM，存在幻觉与不稳定风险。SpecLens 在三个核心环节做了机制性重构：

| 环节 | 常规解法 | SpecLens | 收益 |
|---|---|---|---|
| 参数抽取 | LLM 开放式抽取，抽到什么算什么 | **清单引导式抽取**：把 51 项基线参数作为 checklist 注入提示词，逐参数定位 | 召回率天然收敛到 100%，不存在"没抽到" |
| 差异判定 | LLM 逐条对比 | **确定性对比引擎**：比较方式×数值关系的决策表从 510 行标注数据反推，枚举值映射严格度序数 | 113/113 差异方向全对，零误判，可复现 |
| 可信度 | 信任单次输出 | **双通道交叉校验**：规则通道与 LLM 通道互为对账，不一致即降置信并标记人工复核 | 输出可审计，符合工程评审习惯 |

LLM 的角色从"全知全能的判官"变成"被清单约束、被规则校验的抽取器"——这正是汽车行业功能安全（ISO 26262）对工具链的确定性要求。

## 三、实测效果（对照官方标注 510 行）

| 指标 | 赛题要求 | 实测 |
|---|---|---|
| 参数提取召回率 | ≥95% | **100%**（510/510） |
| 参数提取精确率 | ≥90% | **100%** |
| 要求值抽取准确率 | — | **100%** |
| 差异方向判定（高于/低于/不同） | — | **113/113 = 100%** |
| 满足/不满足误判 | 零误判 | **0 误判 / 0 漏判** |
| 处理速度 | 人工 2-4 h/份 | **10 份 1.7 秒**（离线通道） |

评测口径：`spec_customer_requirements.csv` 的 510 行标注作为 ground truth；差异方向在 113 条差异行上逐条比对。评测脚本随代码交付（`speclens/evaluator.py`），可复现。

```
spec-lens/
├── app.py                  # Streamlit Demo（上传 PDF 实时解析 / 差异矩阵 / 报告下载）
├── run_pipeline.py         # 批量流水线入口（CLI）
├── requirements.txt
├── .env.example            # LLM 配置模板（OpenAI 兼容，可不配）
├── data/
│   ├── pdf/                # 10 份客户规格书 PDF
│   ├── spec_internal_baseline.csv    # 内部能力基线（51 项）
│   ├── spec_customer_requirements.csv # 全量标注（510 行，用于评测）
│   └── spec_gaps_eval_only.csv       # 官方评测集（113 条差异）
├── speclens/
│   ├── pdf_parser.py       # ① PDF 表格/章节解析
│   ├── extractor.py        # ② 双通道抽取 + ③ 交叉校验
│   ├── prompts.py          # 清单引导式抽取提示词
│   ├── llm_client.py       # OpenAI 兼容 LLM 客户端（可降级）
│   ├── value_parser.py     # 要求值归一化（前缀/区间/±/枚举）
│   ├── comparator.py       # ④ 确定性对比引擎（决策表）
│   ├── pipeline.py         # 端到端编排
│   ├── reporter.py         # ⑤ Excel/Markdown 报告
│   └── evaluator.py        # 效果评测（效果数据表数据来源）
└── output/                 # 生成的报告产物
```

## 五、快速开始

```bash
pip install -r requirements.txt

# 离线模式（无需任何 API Key，开箱即用）
python run_pipeline.py --mode offline

# 混合模式（LLM+规则交叉校验）：复制 .env.example 为 .env 并填写 LLM_API_KEY
python run_pipeline.py --mode hybrid

# Demo 界面
streamlit run app.py
```

Demo 三个页签：
1. **上传解析**——上传任意规格书 PDF，实时展示参数级对比结果；
2. **全量差异矩阵**——10 份样例规格书 × 51 项参数，红/黄标色，跨客户类别差异柱状图；
3. **报告导出**——一键下载 Excel 三表报告与 Markdown 差异报告。

## 六、判定口径说明

- **高于**（严于基线）→ 判"不满足"：能力缺口，需专项设计/工艺整改；
- **低于**（宽松于基线）→ 判"满足"：有余量，同时是降本空间（如减配 UV 老化时长）;
- **不同**（区间/口径错配）→ 判"需评估"：需设计与认证联合评估（如 24V 商用车电气平台、美标无 CCC/ECE）。

枚举值严格度序数表（ASIL QM<A<B<C<D、EMC Class/Level、认证 必须>可选>不要求 等）内置于 `comparator.py`，全部由标注数据标定，非人工拍脑袋。

## 七、工程落地路径

- **数据对接**：`data/` 目录即内部标准库的文件形态；替换为真实客户规格书与真实基线即可运行，接口不变；
- **部署形态**：纯 Python + Streamlit，可内网单机部署；离线通道零外呼，满足保密要求；LLM 通道可接内部网关；
- **流程集成**：Excel 三表直接嵌入项目立项评审包（参数明细表 = 评审底稿；差异清单 = 风险项清单；汇总表 = 项目风险看板）。
